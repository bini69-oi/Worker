# Решения

Каждое решение коротко: что выбрали и почему. Новое решение добавляем в конец со следующим номером.

## 1. Go и один бинарник

Бот, API, фоновые задачи и фронт работают в одном процессе.

**Почему:** установка сводится к одному файлу, памяти уходит около 30-50 МБ, запуск меньше секунды.
У Go строгие типы и один стиль кода (gofmt), так что код легко читать любому.

## 2. SQLite вместо Postgres и Redis

Одна база в одном файле, режим WAL (база пишет журнал рядом и не блокирует чтение).

**Почему:** у бота мало записей в секунду, SQLite спокойно тянет десятки тысяч абонентов.
Бэкап это копия файла. Нет отдельных контейнеров, которые надо поднимать и обновлять.

## 3. Только Remnawave

**Почему:** одна панель даёт сквады, вебхуки и HWID, ничего не надо делать дважды.
Клиент панели спрятан за интерфейсом, другую панель можно добавить позже.

## 4. Вся логика в ядре

Папка `core` не знает про Telegram, HTTP и SQL. Бот, Mini App и админка зовут её функции.

**Почему:** покупка и смена тарифа пишутся один раз и закрываются тестами один раз.
Если писать их в каждом интерфейсе отдельно, каждая копия ошибается по-своему.

## 5. Текстовый бот и Mini App, режим выбирает админ

Режимы: только текст, только Mini App, оба.

**Почему:** одним абонентам удобнее кнопки в чате, другим приложение.
Оба режима тонкие и зовут одно ядро, поэтому второй режим не удваивает логику.

## 6. Админка в вебе, в боте только уведомления

Вся настройка в веб-админке. В бот админу приходят уведомления, которые он включает сам.
Под уведомлением кнопки действий: забанить, выдать дни, открыть в админке.
Админки кнопками в чате бота нет.

**Почему:** тарифы и тексты удобно править в браузере, а реагировать быстрее в Telegram.

## 7. Один фронт

Один проект на Svelte, три раздела: Mini App, веб-кабинет, админка. Собирается и вшивается в бинарник.

**Почему:** одна дизайн-система, одна сборка. Mini App и кабинет это одна страница:
в Telegram она берёт вход из Telegram, в браузере входит через бота (решение 15).

## 8. Один источник настроек

В `.env` только токен бота, домен, адрес и ключ панели, ключ шифрования.
Всё остальное лежит в базе в реестре: у каждой настройки есть ключ, тип и значение по умолчанию.
В базе хранятся только отличия от умолчаний.

**Почему:** если значение может прийти и из `.env`, и из админки, правка в админке может молча не сработать.

## 9. Деньги целыми копейками

Все суммы `int64` в копейках (или в минимальных единицах валюты).

**Почему:** дробные числа теряют копейки при сложении.

## 10. Касса одним файлом

У всех касс один интерфейс: создать платёж, проверить вебхук, узнать статус.
Все платежи в одной таблице. Один адрес вебхука `/pay/<касса>`.

**Почему:** новая касса не трогает ядро. Касс хотим много, значит добавлять их должно быть дёшево.

## 11. База главная, панель догоняет

Покупка одной транзакцией в SQLite списывает деньги, продлевает подписку и кладёт задачу
«синхронизировать абонента с панелью» (outbox, очередь задач в той же базе).
Задача выполняется сразу после транзакции. Если панель не ответила, задача повторяется, пока не пройдёт.

**Почему:** деньги и срок подписки никогда не расходятся между собой.
Не бывает «в панели продлили, а в базе нет». Панель просто догоняет то, что записано в базе.

## 12. Угнать бота нельзя одной кражей

Владелец задаётся только в `.env`, сменить его изнутри нельзя. Вход в админку требует пароль и кнопку «Да» в Telegram.
Смена ключей касс, токенов и списка админов требует ещё одной кнопки. Секреты в базе зашифрованы, в журнал не пишутся.
Каждое действие админа записано, а о входах и смене ключей владелец узнаёт сразу.

**Почему:** у бота есть деньги и база абонентов, его будут пробовать угнать. Украденный пароль, сессия или копия базы
по отдельности ничего не дают, а если сервер взломан целиком, владелец видит это сразу и меняет ключи за минуту.

## 13. Темы админ-группы по видам событий

Группа-форум для админов делится на темы по видам событий: Платежи, Пробные, Новые, Поддержка, Ошибки, Безопасность, Сводка.
Каждую тему админ включает сам, кроме «Безопасности».

**Почему:** абонентов могут быть десятки тысяч, тема на каждого превращает группу в свалку.
По видам событий админ сразу видит, где деньги, а где жалобы.

## 14. Поддержка в одной теме, ответ реплаем

Сообщение абонента копируется в тему «Поддержка» с короткой карточкой: имя, ID, тариф, срок, баланс.
Админ отвечает реплаем на это сообщение, бот копирует ответ абоненту. Сообщение без реплая остаётся внутри группы.

**Почему:** не нужна своя система заявок и не нужны темы на каждого. Реплай однозначно говорит, кому ответ,
а обычная переписка админов не утекает абоненту.

## 15. Вход в кабинет из браузера только через бота

Сайт показывает двузначный код и кнопку «Войти через Telegram». Бот спрашивает «Вход на сайт с такого-то браузера?»
и предлагает три кода. Абонент нажимает тот, что видит на сайте. Почты, паролей и входа через соцсети нет.

**Почему:** у каждого абонента уже есть Telegram, а значит и аккаунт. Выбор кода не даёт войти по чужой ссылке:
если злоумышленник прислал свою ссылку входа, абонент не знает его кода. Так же устроен вход в админку.

## 16. Покупка целиком проходит текстом

Всё, что нужно для продажи, есть в текстовом боте: пробный период, покупка, оплата, ссылка, продление.
Mini App повторяет это удобнее, но ничего не добавляет к пути покупки.

**Почему:** когда Telegram работает медленно, текст доходит, а приложение может не открыться.
Абонент, который не смог открыть кабинет, не должен уходить без подписки.

## 17. Типы API пишутся один раз, в Go

Ответы HTTP API описаны структурами Go. Команда `make types` делает из них файл типов TypeScript для фронта,
проверка в CI падает, если файл устарел.

**Почему:** если описать ответ дважды, руками в Go и в TypeScript, однажды они разойдутся, и фронт молча покажет пустое поле.

## 18. Фронт без библиотек сверх необходимого

Svelte, Vite и TypeScript. Маршруты, запросы к API и состояние пишем сами, это по паре десятков строк.
Из готового берём только генератор QR-кода. Шрифты системные, иконки встроенным SVG.

**Почему:** каждая библиотека тянет обновления и уязвимости. Маленькая страница быстро открывается на плохой связи.

## 19. Денежные настройки меняются через «Да» в Telegram

Реквизиты ручной оплаты, курс Stars, проценты рефералки и адрес возврата из кассы меняются так же, как ключи касс:
админка создаёт запрос, владелец подтверждает кнопкой.

**Почему:** угнанная сессия админки могла бы тихо подменить реквизиты, и деньги абонентов ушли бы чужому.

## 20. Разработка с ИИ по одним правилам

Правила для любого ИИ-агента лежат в `AGENTS.md`, процесс в `docs/development.md`.
Задача берётся из `tasks.md`, сначала пишется тест, потом код. Раздел закрывается ревью тремя взглядами:
правильность, безопасность, простота. Каждая находка ревью проверяется по коду до исправления.

**Почему:** ИИ пишет быстро и уверенно, в том числе ошибки. Тест первым и проверка находок по коду ловят их до коммита.
