# Proposal

## Why

У бота деньги и база абонентов, его будут ломать. Защита уже есть в каждой части, но нет общего взгляда:
что именно защищаем, от кого, где слабые места и как это проверяется перед каждым выпуском.

## What Changes

- `docs/security.md`: модель угроз. Кто атакует, что защищаем, чем, что осознанно не закрыто.
- `SECURITY.md`: как сообщить об уязвимости и как выпускается исправление.
- Fuzz-тесты на весь чужой ввод: вебхуки каждой кассы, вебхук панели и Telegram, тела API кабинета и админки, данные кнопок, диплинки.
  CI гоняет каждый fuzz-тест по 30 секунд на каждый push в main.
- Защита HTTP в одном месте: заголовки безопасности на всех ответах, тайм-ауты, предел тела, без версии в ответах.
- Админка по желанию только с разрешённых адресов (`admin.allow_ips`).
- Вебхук панели без секрета не принимается, запуск без секрета панели предупреждает в журнале.
- CI раз в сутки: `govulncheck` по main, падение уходит владельцу.
- Тест «нет секретов в репо»: в коде и истории нет строк, похожих на токены и ключи.
- Чек-лист перед выпуском и живой прогон атак на тестовом сервере: подделка вебхуков, перебор входа, подделка `initData`,
  CSRF на админку, перебор промокодов, флуд бота.

**Не входит:** WAF, защита от DDoS сетевого уровня (это хостер), аудит сторонней фирмой.

## Capabilities

### New Capabilities
- `hardening`: модель угроз, проверки безопасности в CI и перед выпуском.

### Modified Capabilities

Нет. Защита существующих частей не меняет их поведение, кроме отказа вебхука панели без секрета.

## Impact

- Документы: `docs/security.md`, `SECURITY.md`, `docs/release-check.md`.
- Код: `guard` (заголовки и тайм-ауты для всех ответов, список адресов админки), fuzz-тесты по пакетам, `scripts/attack/` для живого прогона.
- CI: fuzz, ночной `govulncheck`, проверка секретов.
