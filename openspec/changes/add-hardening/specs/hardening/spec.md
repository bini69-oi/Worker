# Spec Delta

## Purpose

Общая защита Worker: что проверяется автоматически на каждом изменении и что вручную перед каждым выпуском.

## ADDED Requirements

### Requirement: Модель угроз описана
Репозиторий SHALL содержать `docs/security.md` с таблицей нападающих, их целей и защиты, и `SECURITY.md` с порядком сообщения об уязвимости.

#### Scenario: Новый вход снаружи
- **WHEN** часть добавляет новый адрес HTTP или новый вид ввода
- **THEN** в `docs/security.md` есть строка про него

### Requirement: Fuzz на весь чужой ввод
У каждого разбора чужого ввода SHALL быть fuzz-тест. CI в main гоняет каждый по 30 секунд.

#### Scenario: Касса без fuzz
- **WHEN** в `pay/` есть касса без `Fuzz` на `Verify`
- **THEN** тест-проверка списка fuzz-тестов падает с именем кассы

### Requirement: Заголовки безопасности на всех ответах
Каждый ответ HTTP SHALL нести `X-Content-Type-Options: nosniff` и `Referrer-Policy`, ответы API ещё `Cache-Control: no-store`, без заголовка `Server`.

#### Scenario: Новый адрес
- **WHEN** добавлен новый обработчик HTTP
- **THEN** его ответ с этими заголовками без отдельного кода

### Requirement: Админка по списку адресов
Если `admin.allow_ips` задан, запросы к админке с других адресов SHALL получать 404. Список меняется только через «Да» владельца.

#### Scenario: Чужой адрес
- **WHEN** список `203.0.113.0/24`, запрос с `198.51.100.7`
- **THEN** ответ 404

### Requirement: Вебхук панели только с секретом
Вебхук панели без настроенного секрета SHALL отклоняться, а при запуске без секрета в журнале предупреждение.

#### Scenario: Секрет не задан
- **WHEN** секрет вебхука панели пуст и пришёл вебхук
- **THEN** ответ 401, событие не обработано

### Requirement: Ночная проверка уязвимостей
CI SHALL раз в сутки запускать `govulncheck` по main.

#### Scenario: Найдена уязвимость
- **WHEN** в зависимости появилась уязвимость, до которой доходит код
- **THEN** ночной прогон красный

### Requirement: Нет секретов в репо
Тест SHALL проверять, что в отслеживаемых файлах нет строк, похожих на токен бота, ключи касс и закрытые ключи.

#### Scenario: Токен в тестовых данных
- **WHEN** в `testdata` попал настоящий вид токена бота
- **THEN** тест падает с путём файла

### Requirement: Живой прогон перед выпуском
Перед каждым выпуском набор `scripts/attack` SHALL пройти на тестовом сервере, результат записан в `docs/release-check.md`.

#### Scenario: Подделка прошла
- **WHEN** одна из атак прошла
- **THEN** выпуск не делается, пока она не закрыта
