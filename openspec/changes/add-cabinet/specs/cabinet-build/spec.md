# Spec Delta

## Purpose

Как фронт попадает в бинарник и почему API и фронт не расходятся. Сюда же заголовки безопасности и бюджет размера.

## ADDED Requirements

### Requirement: Фронт вшит в бинарник
Бинарник SHALL отдавать собранный фронт из себя, без файлов рядом. Без сборки фронта бинарник собирается и отдаёт страницу «Фронт не собран».

#### Scenario: Релизная сборка
- **WHEN** выполнены `make web` и `make build`
- **THEN** `/app/` отдаёт страницу кабинета из бинарника

#### Scenario: Сборка без Node.js
- **WHEN** выполнен только `go build ./cmd/worker`
- **THEN** бинарник собран, `/app/` отдаёт «Фронт не собран: выполните make web»

### Requirement: Типы фронта из Go
Файл `web/src/lib/types.gen.ts` SHALL генерироваться из структур ответов `api` командой `make types`. CI падает, если сгенерированный файл отличается от закоммиченного.

#### Scenario: Поле добавили только в Go
- **WHEN** в структуру ответа добавили поле, а `make types` не запускали
- **THEN** CI упал с сообщением «типы устарели: make types»

### Requirement: Общие эталоны ответов
Тесты фронта SHALL брать ответы сервера из `api/testdata/*.json`, которые пишут тесты Go.

#### Scenario: Сервер переименовал поле
- **WHEN** тест Go обновил эталон с переименованным полем
- **THEN** тест фронта, который читал старое поле, упал

### Requirement: Проверки фронта
`make web-check` SHALL запускать `svelte-check`, тесты vitest, проверку размера и `npm audit` на уязвимости уровня high и выше. CI запускает его на каждый push.

#### Scenario: Уязвимая зависимость
- **WHEN** `npm audit` нашёл уязвимость high
- **THEN** CI упал

### Requirement: Бюджет размера
JS и CSS кабинета SHALL весить не больше 80 КБ в gzip. Больше: `make web-check` падает и печатает размер.

#### Scenario: Тяжёлая библиотека
- **WHEN** в кабинет добавили библиотеку на 200 КБ
- **THEN** `make web-check` упал с размером сборки

### Requirement: Заголовки безопасности
Ответы `/app/` SHALL нести `Content-Security-Policy` с разрешёнными скриптами только со своего адреса и `telegram.org`, встраиванием только в `web.telegram.org`, а также `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`.

#### Scenario: Встроили в чужой сайт
- **WHEN** чужой сайт встроил `/app/` во фрейм
- **THEN** браузер не показал страницу

### Requirement: Кэш статики
Файлы с хэшем в имени SHALL отдаваться с кэшем на год, `index.html` без кэша.

#### Scenario: Новая версия
- **WHEN** вышла новая версия, и абонент открыл кабинет
- **THEN** он получил новый `index.html` и новые файлы, старые из кэша не мешают
