# Spec Delta

## Purpose

HTTP API, через которое страница кабинета зовёт ядро. API ничего не решает само: берёт абонента из сессии, проверяет форму запроса и передаёт ядру.

## ADDED Requirements

### Requirement: Абонент только из сессии
Каждый обработчик кабинета SHALL брать id абонента из сессии. Id абонента в теле или адресе запроса не принимается.

#### Scenario: Чужой платёж
- **WHEN** абонент запросил `GET /api/app/payments/43`, а платёж 43 чужой
- **THEN** ответ 404, данные платежа не отданы

### Requirement: Те же сценарии, что в боте
Покупка, пробный период, пополнение, промокод, устройства и автопродление SHALL идти через те же функции ядра, что зовёт бот. В `api` нет своей логики денег и подписок.

#### Scenario: Покупка без денег
- **WHEN** абонент купил тариф за 250 ₽ при балансе 100 ₽
- **THEN** ответ с кодом `E2001`, ценой, балансом и недостачей 150 ₽, корзина запомнена ядром

### Requirement: Ошибки одним видом
Ошибка SHALL отдаваться JSON `{"code", "text"}` с HTTP-статусом 4xx или 5xx. Текст берётся по ключу на языке абонента. Внутренняя ошибка не раскрывает подробностей, только код.

#### Scenario: Неизвестный тариф
- **WHEN** абонент купил тариф с несуществующим id
- **THEN** ответ 404 `{"code": "E…", "text": "Тариф не найден"}`

#### Scenario: Сбой базы
- **WHEN** база вернула ошибку
- **THEN** ответ 500 с кодом, в тексте нет SQL и путей, подробности только в журнале

### Requirement: Форма запроса проверяется
Тело запроса SHALL быть JSON не больше 16 КБ без неизвестных полей. Иначе ответ 400.

#### Scenario: Лишнее поле
- **WHEN** в теле `POST /api/app/buy` есть поле `user_id`
- **THEN** ответ 400, покупки нет

#### Scenario: Большое тело
- **WHEN** тело 1 МБ
- **THEN** ответ 413, тело не прочитано целиком

### Requirement: Защита от подделки запроса
Изменяющий запрос с cookie SHALL требовать заголовок `X-Worker: 1` и `Content-Type: application/json`. Запрос с токеном в `Authorization` этого не требует.

#### Scenario: Форма с чужого сайта
- **WHEN** чужой сайт отправил форму на `POST /api/app/promo` с cookie абонента
- **THEN** ответ 403, промокод не применён

### Requirement: Лимит запросов
API SHALL принимать не больше 10 запросов в секунду на сессию. Лишние получают 429.

#### Scenario: Скрипт долбит API
- **WHEN** с одной сессии пришло 50 запросов за секунду
- **THEN** 10 обработаны, 40 получили 429

### Requirement: Техработы и бан
При включённых техработах API SHALL отвечать на действия абонента кодом `ErrMaintenance`, а `GET /api/app/me` возвращать признак техработ. Забаненный абонент получает 403 на любой запрос.

#### Scenario: Техработы
- **WHEN** техработы включены и абонент открыл кабинет
- **THEN** страница показывает текст о техработах

### Requirement: Статус оплаты сверяется
`GET /api/app/payments/{id}` SHALL для ожидающего платежа просить ядро сверить его с кассой не чаще раза в 3 секунды.

#### Scenario: Вебхук задержался
- **WHEN** абонент оплатил, вебхук ещё не пришёл, страница спросила статус
- **THEN** ядро сверило платёж с кассой, ответ «оплачен», баланс пополнен
