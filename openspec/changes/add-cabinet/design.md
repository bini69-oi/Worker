# Design

## Context

Ядро и бот готовы. Кабинет повторяет путь бота в приложении и в браузере и добавляет удобство: QR, история, устройства.
Логика остаётся в ядре (решение 4), покупка целиком проходит и в боте (решение 16).

## Goals / Non-Goals

**Goals:**
- Одна страница для Telegram и браузера, один набор вызовов API.
- API и фронт не расходятся: типы из Go, эталоны ответов общие для тестов обеих сторон.
- Страница открывается быстро на плохой связи.

**Non-Goals:**
- Админка: отдельная часть, но этот же сервер, сборка и подход.
- Вход без Telegram-аккаунта.

## Decisions

### Папки

| Папка | Что внутри | Зависит от |
|---|---|---|
| `api` | роутер, сессии, JSON, ошибки, обработчики кабинета по файлу на тему | `core`, `texts`, `tgsign`, `guard`, `apps` |
| `api/testdata` | эталоны ответов API | |
| `web/src/app` | экраны кабинета | `web/src/lib` |
| `web/src/lib` | запросы к API, маршруты, Telegram, тема, тексты, `types.gen.ts` | |
| `web/embed.go` | вшивание сборки в бинарник | |
| `cmd/gen-types` | генерация `types.gen.ts` из структур ответов `api` | `api` |

### Адреса

| Адрес | Что |
|---|---|
| `/app/` | страница кабинета |
| `/api/app/*` | API кабинета |
| `/dl/<app>/<токен>` | переход в приложение (из части бота) |

Маршруты внутри страницы через `#`: `/app/#/buy`. **Почему:** серверу не нужно знать маршруты фронта, а Telegram открывает адрес как есть.

### Вход в Telegram

1. Страница видит в адресе `tgWebAppData` и только тогда загружает `telegram-web-app.js`.
2. Отправляет `initData` на `POST /api/app/session/tg`.
3. Сервер проверяет подпись (`tgsign`) и свежесть (не старше часа), регистрирует абонента, если его нет, выдаёт токен сессии на 24 часа.
4. Токен хранится в памяти страницы и в `sessionStorage`, идёт заголовком `Authorization: Bearer`.

**Почему не cookie:** в WebView Telegram сторонние cookie работают не везде. Заголовок работает всегда.

### Вход в браузере

1. `POST /api/app/login` создаёт запрос входа на 5 минут и отвечает: id запроса, двузначный код, ссылка `t.me/<бот>?start=web_<nonce>`.
2. Абонент открывает ссылку. Бот пишет: «Вход на сайт: IP, устройство» (браузер и система только из белого списка по User-Agent, остальное «неизвестное устройство») и показывает три кода с предупреждением: нажимайте код, только если видите его сами, иначе «Это не я».
3. Абонент нажимает код. Ядро сравнивает его с кодом запроса за постоянное время. Неверный код сразу закрывает запрос и идёт в счёт: три за час закрывают вход в браузере для абонента на час.
4. Страница раз в 2 секунды спрашивает `GET /api/app/login/<id>`. После подтверждения сервер ставит cookie сессии на 30 дней
   (`HttpOnly`, `Secure`, `SameSite=Strict`, путь `/api/app`).

id запроса знает только браузер, `nonce` только ссылка. **Почему код, а не просто «Да»:** если злоумышленник пришлёт свою ссылку входа,
абонент не знает кода на экране злоумышленника. Так же устроен вход в админку (решение 15).

### Сессии абонента

Таблица `user_sessions`, в базе только SHA-256 токена.

| Вид | Срок | Без движения |
|---|---|---|
| Telegram | 24 часа | не ограничено |
| браузер | 30 дней | 7 дней |

«Выйти на всех устройствах» закрывает все сессии абонента. Бан закрывает все сессии сразу.

### Защита запросов

- Изменяющий запрос с cookie требует заголовок `X-Worker: 1` и `Content-Type: application/json`. Чужой сайт такой запрос без CORS не пошлёт.
- Тело не больше 16 КБ, неизвестные поля JSON отклоняются.
- Не больше 10 запросов в секунду на проверенную сессию (без неё на IP, IPv6 по /64) и 10 запусков входа за 10 минут с одного IP (`guard`); входы Mini App 60 в минуту с IP и 10 за 10 минут на Telegram ID; изменяющему запросу с cookie сессии всегда нужен `X-Worker`, при заголовке Authorization cookie не смотрится.
- Покупка, докупка и отмена смены несут ключ повтора (16-64 знака): ядро записывает его в той же транзакции, что и списание, повтор ничего не списывает.
- Ответ об ошибке: `{"code": "E2001", "text": "..."}`, текст по ключу на языке абонента.

### API кабинета

| Метод и адрес | Что делает | Функция ядра |
|---|---|---|
| `GET /api/app/me` | главная: абонент, подписка, баланс, доступен ли пробный, кассы | `Sub`, `Gateways`, данные абонента |
| `GET /api/app/texts` | тексты `app.*` и `err.*` на языке абонента | `texts` |
| `POST /api/app/trial` | пробный период | `Trial` |
| `GET /api/app/tariffs` | тарифы и сроки | `Tariffs` |
| `POST /api/app/quote` | цена, баланс, недостача | `Quote` |
| `POST /api/app/buy` | покупка, при недостаче запоминает корзину | `Buy`, `RememberBuy` |
| `POST /api/app/topup` | пополнение: ссылка кассы или счёт Stars | `CreatePayment` |
| `GET /api/app/payments/{id}` | статус своего платежа, сверка с кассой | `CheckPayment` |
| `GET /api/app/history` | движения баланса | `History` |
| `GET /api/app/connect` | приложения, переходы `/dl`, ссылка подписки | `apps`, `Sub` |
| `GET /api/app/devices`, `DELETE /api/app/devices/{hwid}`, `POST /api/app/devices/reset` | устройства | `Devices`, `DeleteDevice`, `ResetDevices` |
| `POST /api/app/link/revoke` | перевыпуск ссылки | `RevokeLink` |
| `POST /api/app/promo` | промокод | `ApplyPromo` |
| `GET /api/app/ref` | ссылка и статистика рефералки | `RefStats` |
| `POST /api/app/autorenew` | автопродление | `SetAutoRenew` |
| `POST /api/app/plan/cancel` | отмена ждущей смены тарифа | `CancelPlan` |
| `POST /api/app/addons/traffic`, `POST /api/app/addons/device` | докупка трафика и устройства | `BuyTraffic`, `BuyDevice` |
| `POST /api/app/logout`, `POST /api/app/logout-all` | выход | сессии ядра |

Каждый обработчик берёт id абонента только из сессии. **Почему:** id в теле запроса можно подменить, сессию нет.

### Оплата из кабинета

- Внутри Telegram Stars идут через `createInvoiceLink` и `WebApp.openInvoice`. В браузере Stars не показываются.
- Остальные кассы: `openLink` (в Telegram) или новая вкладка (в браузере), потом опрос статуса раз в 3 секунды до 10 минут.
- Адрес возврата из кассы для платежей из кабинета в браузере ведёт на `/app/#/pay/<id>` (платёж помечен `source=web`), из Mini App в бота, как раньше: внешний браузер Mini App не вернёт в Telegram. Настройка адреса возврата у кассы главнее.

### Фронт

- Svelte 5, Vite, TypeScript. Маршруты, запросы и состояние свои, по паре десятков строк (решение 18).
- Две точки входа сборки: `app` и `admin`. Общее в `lib`.
- Тексты страницы приходят из `GET /api/app/texts`. В коде фронта нет строк, которые видит абонент.
- Тема: CSS-переменные. В Telegram переменные берутся из `themeParams`, в браузере из `prefers-color-scheme`.
- В Telegram кнопка «Назад» Telegram ведёт по истории страницы, на главной скрыта.
- Бюджет: JS и CSS кабинета не больше 80 КБ в gzip. Проверяет `make web-check`.

### Типы

`cmd/gen-types` читает структуры ответов из `api` через `reflect` и пишет `web/src/lib/types.gen.ts`.
CI запускает генерацию и падает, если файл изменился. **Почему генерация, а не схема OpenAPI:** структура Go уже есть,
а генератор на сотню строк проще, чем схема и её инструменты.

### Сборка

- Vite собирает в `web/build`. В git лежит только заглушка `web/build/README.txt`.
- `web/embed.go` вшивает `web/build` через `embed`. Без сборки сервер отдаёт страницу «Фронт не собран: выполните `make web`».
- `make web` собирает фронт, `make build` собирает бинарник с фронтом. Релиз всегда с фронтом.

| Заголовок | `/app/` |
|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' https://telegram.org; frame-ancestors https://web.telegram.org` |

| Таблица | Поля | Зачем |
|---|---|---|

### Тесты

- `api`: `httptest`, настоящее ядро на SQLite во временном файле, фейковые панель и касса. Ответы сверяются с `api/testdata/*.json`.
- Фронт: vitest берёт те же `api/testdata/*.json` как ответы сервера. `svelte-check` проверяет типы.
- Fuzz: разбор JSON тел запросов.
- Сквозной тест API: вход через бота, пробный, пополнение, покупка, устройства, выход.

## Risks / Trade-offs

- [Node.js нужен для сборки] → только разработчику и CI. Пользователь получает готовый бинарник.
- [Опрос статуса входа и оплаты] → редкие запросы с паузой 2-3 секунды, с пределом по времени. Проще вебсокетов.
- [Злоумышленник подсказал абоненту код] → в сообщении бота прямо написано, что код нужен только если абонент сам входит на сайт сейчас.
- [Telegram Web во фрейме] → `frame-ancestors` разрешает только `web.telegram.org`.

## Migration Plan

Миграция `005_cabinet.sql` только добавляет таблицы. Откат: старый бинарник их не читает.
