# Design

## Context

Ядро уже умеет вход админа (пароль и код в Telegram), сессии, права, журнал действий, подтверждения опасных действий,
тарифы, промокоды, ручное зачисление и возврат Stars. Кабинет дал HTTP API, сессии, сборку фронта и генерацию типов.
Админка добавляет сайт поверх и недостающие функции ядра.

## Goals / Non-Goals

**Goals:**
- Каждое действие админки это одна функция ядра с проверкой прав и записью в журнал в той же транзакции.
- Помощник видит и может только то, что отмечено в его правах. Права проверяет ядро, сайт только прячет недоступное.
- Админка работает на телефоне: админ часто отвечает с телефона.

**Non-Goals:**
- Админка в Telegram кнопками (решение 6). В Telegram только уведомления с кнопками из части бота.
- Действия над сервером: обновление, перезапуск, бэкапы.

## Decisions

### Адреса

| Адрес | Что |
|---|---|
| `/admin/` | страница админки |
| `/api/admin/*` | API админки |

`/admin/#/users/<id>` открывает карточку абонента. На этот адрес ведёт кнопка «Открыть в админке» из уведомлений.

### Вход и сессии

Ядро уже умеет: `LoginStart`, `AnswerLogin`, `LoginFinish`, `SessionAdmin`, `Sessions`, `CloseSession`.

1. `POST /api/admin/login` с Telegram ID и паролем. Ответ: id шага и код для экрана.
2. Админ выбирает этот код в сообщении бота.
3. Страница опрашивает `GET /api/admin/login/{id}`. После подтверждения cookie `HttpOnly`, `Secure`, `SameSite=Strict`, путь `/api/admin`.

Изменяющие запросы требуют `X-Worker: 1` и `Content-Type: application/json`, как в кабинете.
Cookie админки и кабинета разные и живут на разных путях.

### Права

| Право | Что открывает |
|---|---|
| `users` | поиск и карточка абонента |
| `grant` | деньги и дни абоненту, ручное подтверждение платежа |
| `ban` | бан и разбан |
| `promo` | промокоды |
| `tariffs` | тарифы |
| `broadcast` | рассылки |
| `stats` | сводка и список платежей |
| `support` | сообщение абоненту |

Только владелец: тексты, настройки, кассы, уведомления, команда, журнал действий, техработы, возврат Stars.

**Почему тексты и настройки только владельцу:** правка текста меняет то, что видят все абоненты. Помощнику это не нужно каждый день,
а ошибка в тексте бьёт по всем сразу.

`GET /api/admin/me` отдаёт права. Сайт прячет разделы без прав, но каждый адрес всё равно проверяется ядром.

### Что получает ядро

| Функция | Право | Зачем |
|---|---|---|
| `FindUsers(actor, query, filter, cursor)` | `users` | поиск по Telegram ID, `@username`, коду рефералки; фильтр по статусу |
| `UserCard(actor, userID)` | `users` | абонент, подписка, баланс, последние 50 движений и платежей, журнал по нему |
| `SendToUser(actor, userID, text)` | `support` | сообщение абоненту через очередь |
| `Payments(actor, filter, cursor)` | `stats` | платежи с фильтром по статусу, кассе, датам |
| `Promos(actor, cursor)` | `promo` | список промокодов с числом активаций |
| `Stats(actor, from, to)` | `stats` | сводка за период |
| `SetText`, `ResetText(actor, key, lang, …)` | владелец | правка текстов |
| `SetSetting`, `ResetSetting(actor, key, …)` | владелец | правка настроек |
| `Audit(actor, filter, cursor)` | владелец | журнал действий |
| `CreateBroadcast`, `StartBroadcast`, `CancelBroadcast`, `Broadcasts`, `TestBroadcast` | `broadcast` | рассылки |
| `GatewayStates(actor)` | владелец | касса включена, ключи есть, последний оплаченный платёж, сколько ждут |

Списки отдаются страницами по 50 с курсором по id. **Почему курсор, а не номер страницы:** новые строки не сдвигают страницы.

### Настройки

- Обычная настройка меняется сразу, пишется в журнал.
- Секретная (ключи касс, токены) идёт через `RequestSecret`, применяется после «Да» владельца.
- Денежная (группа `money`: реквизиты ручной оплаты, курс Stars, проценты рефералки, адрес возврата из кассы)
  идёт через `RequestAction` и тоже ждёт «Да» (решение 19).
- У настройки может быть своя проверка: `connect.apps` только известные приложения, `notify.security` нельзя выключить.
- Секреты в ответах API только маской: `••••1a2b`.

### Тексты

Экран текстов показывает ключ, умолчание, текущее значение и список подстановок. `texts.Set` уже проверяет, что подстановки
в новом тексте известны. Сверх этого: подпись кнопки до 64 символов, сообщение до 4096.

### Рассылки

| Поле `broadcasts` | Что |
|---|---|
| id, segment, text, button_text, button_url | что и кому |
| status | `draft`, `running`, `done`, `cancelled` |
| total, sent, failed, blocked | счётчики |
| cursor_user_id | до какого абонента дошли |
| created_by, created_at, started_at, done_at | кто и когда |

- Сегменты: все, с подпиской, без подписки, истекла за 30 дней, на пробном. Забаненные и недоступные не получают никогда.
- Текст: разметка Telegram HTML, разрешены `b`, `i`, `u`, `s`, `a`, `code`, `pre`, `blockquote`. Ссылки только `https` и `tg`.
  Разметку проверяет ядро при сохранении.
- Отправка: задача в `jobs`, 25 сообщений в секунду, абоненты по возрастанию id. После каждого отправленного `cursor_user_id`
  сохраняется. После перезапуска рассылка продолжается с курсора, повтор не больше одного сообщения.
- Отмена останавливает рассылку после текущего сообщения.

**Почему курсор, а не таблица получателей:** таблица на десятки тысяч строк на каждую рассылку не нужна, когда порядок по id стабилен.

### Сводка и итог дня

`Stats` считает по `payments`, `ledger`, `users`, `subscriptions`: выручка по дням, новые, пробные, оплатившие впервые,
активные подписки, зависшие задачи `outbox`. Итог дня: задача в `jobs` в час из настройки `summary.hour` (по умолчанию 9)
шлёт `Stats` за вчера в тему «Сводка».

### Фронт

- Точка входа `admin` в том же проекте `web`, общий `lib`.
- Разделы: Сводка, Абоненты, Платежи, Тарифы, Промокоды, Рассылки, Тексты, Настройки, Кассы, Уведомления, Команда, Журнал.
- Таблицы на телефоне становятся карточками.
- Тексты админки на русском в коде фронта. **Почему исключение из «тексты по ключу»:** админку видит только владелец и его команда,
  а редактор текстов для текстов самой админки это лишняя сложность.
- Бюджет: JS и CSS админки не больше 200 КБ в gzip.

### Заголовки

Как у кабинета, но `frame-ancestors 'none'` и `script-src 'self'`: админка не открывается во фрейме и не грузит скрипт Telegram.

### Новые данные

Миграция `004_admin.sql`: таблица `broadcasts`, индексы `users(username)`, `payments(status, created_at)`, `audit_log(created_at)`.

### Тесты

- Ядро: таблицы сценариев на каждую функцию, отдельный тест «помощник без права» на каждую.
- `api`: эталоны ответов, тест «нет права, 403» на каждый адрес из таблицы прав. Таблица прав в тесте та же, что в коде.
- Рассылка: фейковый Telegram, фейковые часы, тест «перезапуск посередине».
- Фронт: vitest на эталонах API.

## Risks / Trade-offs

- [Рассылка задевает лимиты Telegram] → 25 в секунду с запасом под общий лимит, 429 ждёт `retry_after`.
- [Помощник с правом `users` листает базу] → списки по 50, выгрузки нет, право выдаёт только владелец.
- [Тексты админки не переводятся] → осознанно: админка для команды владельца.
- [Сводка медленная на большой базе] → индексы из миграции, период до 90 дней.

## Migration Plan

Миграция `004_admin.sql` только добавляет таблицу и индексы. Откат: старый бинарник их не читает.
