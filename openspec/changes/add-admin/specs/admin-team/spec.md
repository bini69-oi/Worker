# Spec Delta

## Purpose

Кто работает в админке и что делал: помощники с правами, их сессии и журнал действий. Функции добавления и удаления помощников уже есть в ядре и требуют «Да» владельца.

## ADDED Requirements

### Requirement: Помощники
Владелец SHALL видеть список помощников с правами, добавлять помощника (Telegram ID, пароль, права) и убирать его. Добавление и удаление применяются после «Да» в Telegram.

#### Scenario: Добавил помощника
- **WHEN** владелец добавил помощника с правами `users` и `support` и нажал «Да»
- **THEN** помощник входит и видит только Абонентов

#### Scenario: Без прав
- **WHEN** владелец не отметил ни одного права
- **THEN** помощник не добавлен, ответ с кодом ошибки

### Requirement: Сессии
Владелец SHALL видеть открытые сессии всех админов (кто, IP, браузер, когда последний раз) и закрывать любую.

#### Scenario: Закрыл чужую сессию
- **WHEN** владелец закрыл сессию с незнакомого IP
- **THEN** следующий запрос с этой сессией получает 401

### Requirement: Журнал действий
Владелец SHALL видеть журнал действий страницами по 50 с фильтром по админу, действию и датам. В журнале нет секретов. Журнал нельзя править и удалять из админки.

#### Scenario: Кто выдал дни
- **WHEN** владелец отфильтровал журнал по действию «выдать дни»
- **THEN** он видит, кто, кому, сколько дней и когда

#### Scenario: Смена ключа в журнале
- **WHEN** в журнале запись о смене ключа кассы
- **THEN** в ней видно, какой ключ сменён, значения ключа нет

### Requirement: Пароль владельца не меняется из админки
Раздел команды SHALL не давать сменить пароль владельца. Пароль владельца задаётся только командой на сервере.

#### Scenario: Попытка сменить пароль владельца
- **WHEN** запрос на смену пароля владельца пришёл в API админки
- **THEN** такого адреса нет, ответ 404
