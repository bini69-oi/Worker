# Design

## Context

Интерфейс кассы, общий набор тестов и вебхук `/pay/{name}` уже есть (`add-core`). Пять касс написаны.

## Decisions

### Касса одним файлом
Каждая касса это `pay/<имя>/<имя>.go` и тест. Ядро не меняется. **Почему:** так 27 касс не трогают друг друга и пишутся параллельно.

### Протокол по открытым источникам
Адреса API, подписи и статусы берутся из документации кассы. Если касса не подписывает вебхук, `Verify` верит только ответу её API.
**Почему:** поддельный вебхук без подписи иначе зачислял бы деньги.

### Выключены по умолчанию
Новая касса появляется у абонента, только когда админ включил её и заполнил ключи.

### Проверка на живой кассе
Тест проверяет протокол на записанных примерах. Настоящий счёт проверяется на тестовом сервере с ключами владельца,
список проверенных касс ведётся в `docs/gateways.md`.

## Risks / Trade-offs

- [Касса поменяла API] → записанные примеры в тестах, поломка видна сразу, касса чинится своим файлом.
- [Протокол восстановлен по чужому коду, а не по документации] → отмечено в `docs/gateways.md`, касса не считается проверенной до живого платежа.
