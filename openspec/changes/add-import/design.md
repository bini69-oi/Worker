# Design

## Decisions

### Подписка с лимитами из панели
У перенесённой подписки нет нашего тарифа: лимиты тарифа в панели могли быть любыми. Подписка получает снимок лимитов:

| Поле подписки | Откуда |
|---|---|
| `imported` | признак переноса |
| `own_traffic_bytes`, `own_devices`, `own_reset`, `own_squads` | лимиты пользователя в панели |
| `panel_uuid`, `sub_url`, `expires_at`, `status` | как в панели |

`panelUser` для такой подписки берёт снимок, а не тариф, поэтому сверка с панелью не затирает лимиты.

**Почему снимок, а не тариф «импорт»:** у пользователей разные лимиты, один тариф их бы обрезал.

### Продление перенесённой подписки
Абонент продлевает, выбирая наш тариф. Покупка тарифа при живой перенесённой подписке идёт как смена тарифа со следующего периода
(`add-plans`): срок перенесённой подписки доживает, дальше включается купленный тариф. После окончания без покупки подписка истекает
как обычная.

### Сопоставление
- Ключ абонента: Telegram ID из панели. Есть у нас абонент с этим ID и без подписки: подписка привязывается к нему.
  Есть абонент с подпиской: пользователь пропускается с причиной «уже есть подписка».
- Ключ подписки: `panel_uuid`. Подписка с таким `panel_uuid` уже есть: пропуск, повтор не создаёт дублей.
- Нет Telegram ID: пропуск с причиной. Такие пользователи остаются в панели как были.
- Отключён в панели (DISABLED): пропуск. Перенос с включённой подпиской снял бы чужую блокировку при сверке.
- Имя пользователя в панели сохраняется навсегда, и после перехода на наш тариф: сверка его не переименовывает.
- Перенесённому пробный период не положен, докупка и автопродление недоступны до покупки нашего тарифа.

### Безопасность
- Только владелец: команда на сервере или кнопка с подтверждением «Да» в Telegram.
- Импорт ничего не пишет в панель: только чтение. Панель догонит базу только при следующей сверке, а состояние уже совпадает.
- Строки панели это чужой ввод: длины, формат uuid, даты, лимиты проверяются, мусор пропускается с причиной.
- Итог в журнал действий и тревогой владельцу: число заведённых, пропущенных и причины.

### Пробный прогон
Без `--apply` импорт считает всё в одной транзакции и откатывает её. Отчёт тот же, что при записи.

## Risks / Trade-offs

- [Один Telegram ID у двух пользователей панели] → заводится первый по дате создания, второй пропускается с причиной.
- [Пользователь панели продлён руками после импорта] → сверка вернёт срок из базы (как для всех), владельцу это сказано в отчёте.
- [Большая панель] → список читается страницами по 500, запись одной транзакцией на 500 пользователей.
