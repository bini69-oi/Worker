# Spec Delta

## Purpose

Связь с Telegram: как бот получает обновления и как отправляет сообщения. Без лишних библиотек и без потери обновлений.

## ADDED Requirements

### Requirement: Обновления приходят вебхуком
В рабочем режиме бот SHALL получать обновления вебхуком на `PUBLIC_URL`. При старте бот сам ставит вебхук со случайным секретом и проверяет заголовок `X-Telegram-Bot-Api-Secret-Token` у каждого запроса.

#### Scenario: Старт
- **WHEN** процесс запускается
- **THEN** вебхук указывает на `PUBLIC_URL`, секрет новый, старый секрет больше не принимается

#### Scenario: Запрос без секрета
- **WHEN** на адрес вебхука пришёл запрос без верного заголовка
- **THEN** ответ 401, обновление не обработано

### Requirement: Режим опроса для разработки
Если в настройках включён режим опроса, бот SHALL снимать вебхук и забирать обновления методом `getUpdates`. Это нужно, чтобы запускать бота на своём компьютере без https.

#### Scenario: Опрос
- **WHEN** включён режим опроса
- **THEN** вебхук снят, обновления приходят через `getUpdates`

### Requirement: Обновление обрабатывается один раз
Повтор одного обновления от Telegram SHALL не выполнять действие второй раз.

#### Scenario: Telegram прислал обновление дважды
- **WHEN** приходит обновление с тем же `update_id`
- **THEN** второе игнорируется

### Requirement: Ответ на вебхук быстрый
Бот SHALL отвечать Telegram на вебхук сразу, а обрабатывать обновление после ответа. Медленная касса или панель не задерживает ответ.

#### Scenario: Касса отвечает 10 секунд
- **WHEN** обработка обновления ждёт кассу
- **THEN** Telegram получил 200 сразу и не прислал обновление повторно

### Requirement: Лимиты Telegram соблюдаются
Клиент SHALL не превышать лимиты Telegram на отправку и при ответе 429 ждать указанное в ответе время, а потом повторять.

#### Scenario: Ответ 429
- **WHEN** Telegram ответил 429 с `retry_after: 3`
- **THEN** сообщение отправлено повторно не раньше чем через 3 секунды
