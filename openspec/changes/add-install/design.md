# Design

## Decisions

### Где что лежит на сервере

| Путь | Что | Права |
|---|---|---|
| `/usr/local/bin/worker` | бинарник | root, 755 |
| `/etc/worker/env` | токены и ключ | root:worker, 640 |
| `/var/lib/worker/` | база, замок, бэкапы | worker, 700 |
| `/etc/caddy/Caddyfile` | https для домена | root |

Служба работает от пользователя `worker` без оболочки и без прав root. Слушает только `127.0.0.1:8080`, наружу ходит через Caddy.

### Служба systemd в песочнице

`NoNewPrivileges`, `ProtectSystem=strict`, `ReadWritePaths=/var/lib/worker`, `ProtectHome`, `PrivateTmp`, `PrivateDevices`,
`ProtectKernelTunables`, `ProtectKernelModules`, `ProtectControlGroups`, `RestrictNamespaces`, `LockPersonality`,
`MemoryDenyWriteExecute`, `RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX`, `SystemCallFilter=@system-service`,
`CapabilityBoundingSet=` пустой, `UMask=0077`, `Restart=on-failure`.
**Почему:** если в боте найдут дыру, процесс не сможет писать вне своей папки, ставить программы и подниматься в root.
Проверка: `systemd-analyze security worker` даёт оценку не выше 2.0 («OK»).

### Установка

1. Проверка: root, Debian 11+ или Ubuntu 22.04+, amd64 или arm64, свободные 80 и 443 (иначе отдельный путь ниже).
2. Скачивание релиза и `SHA256SUMS` с подписью `SHA256SUMS.sig`. Подпись Ed25519 проверяется `openssl` открытым ключом,
   вшитым в сам `install.sh`. Не сошлась подпись или сумма: установка останавливается.
3. Вопросы: токен бота (проверка `getMe`), Telegram ID владельца, домен (проверка, что A-запись смотрит на этот сервер),
   адрес и токен панели (проверка запросом версии). Ключ шифрования создаётся сам и показывается один раз.
4. Пароль владельца для админки задаётся там же командой `worker admin password`.
5. Caddy из официального репозитория, Caddyfile с доменом, https сам.
6. Служба включается, установщик ждёт `GET /healthz` и пишет адрес бота и админки.

Если 80 или 443 заняты (на сервере уже стоит панель с nginx), Caddy не ставится, установщик печатает готовый кусок конфига nginx.

### Релиз и подпись

- По тегу `vX.Y.Z` CI собирает `worker-linux-amd64` и `worker-linux-arm64` с фронтом, считает `SHA256SUMS` и подписывает его
  Ed25519 ключом из секрета репозитория. `cmd/sign` это 40 строк на стандартной библиотеке.
- Открытый ключ лежит в `install/release.pub`, вшит в `install.sh` и в бинарник (`worker update`).
- **Почему своя подпись, а не только HTTPS GitHub:** угнанный аккаунт или токен CI не подпишет релиз без отдельного ключа.

### Обновление

`worker update [--version vX.Y.Z]`: скачивает, проверяет подпись встроенным ключом, делает бэкап, кладёт новый бинарник рядом,
меняет атомарным переименованием, перезапускает службу, ждёт `/healthz` 60 секунд. Не поднялся: возвращает старый бинарник
и перезапускает. Миграции базы только добавляют, поэтому старый бинарник с новой базой работает.

### Бэкап

- `VACUUM INTO` во временный файл (согласованная копия без остановки), шифрование AES-256-GCM ключом,
  выведенным из `SECRET_KEY` через HMAC с меткой «backup», запись `backups/worker-YYYYMMDD-HHMMSS.db.enc`.
- Ежедневная фоновая задача, хранится `backup.keep` последних (по умолчанию 14).
- `worker restore <файл>`: только при остановленной службе (замок базы), расшифровка, `PRAGMA integrity_check`,
  текущая база сохраняется рядом, потом подменяется.
- `worker backup --check <файл>`: расшифровать и проверить целостность без восстановления.

## Risks / Trade-offs

- [Потерян SECRET_KEY] → бэкапы не расшифровать. Установщик показывает ключ один раз и прямо пишет, куда его сохранить.
- [Ключ подписи релизов утёк] → новый ключ, новый `install.sh`; старые установки обновляются вручную. Описано в `SECURITY.md`.
- [Панель на том же сервере занимает 443] → путь с nginx, без Caddy.
