# Design

## Decisions

### Английский рядом с русским
`texts.Def` получает поле `En`. Умолчания на двух языках лежат в одном месте, поэтому новый ключ без перевода сразу виден в диффе и тесте.
`Raw(key, lang)`: правка админа на языке абонента, потом умолчание на языке абонента (`ru` или `en`), потом язык по умолчанию из настроек.

**Почему не файлы локалей:** один источник текстов (решение 8), правка в админке перекрывает умолчание, отдельных JSON-файлов нет.

### Язык абонента
- При регистрации: `ru` для кодов `ru`, `uk`, `be`, `kk`; `en` для остальных; если кода нет, язык по умолчанию из настроек.
- `Langs()` отдаёт `ru`, `en` и языки правок админа. Кнопка языка видна всегда, раз языков два.

### Проверка
Тест проходит все `Def`: `En` не пустой, подстановки в `En` те же, что в `Params`, разметка HTML закрыта.
Тест бота: эталоны главного меню и экрана подписки на английском.

## Risks / Trade-offs

- [Перевод машинный и кривой] → тексты пишутся человеком при реализации, админ правит любой текст в админке.
